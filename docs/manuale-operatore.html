1 Il sistema in breve

Il server OpenTAKServer gira su n3test002 e collega i client TAK (ATAK su Android, iTAK su iPhone, WinTAK su PC). Ogni informazione che un client invia — posizione, marker, chat, file — è un messaggio CoT (Cursor-on-Target) che attraversa questa catena:

ATAK ──SSL 8089──▶ eud_handler ──▶ RabbitMQ ──▶ cot_parser ──▶ PostgreSQL
                                        │                          │
                                        ▼                          ▼
                                 altri client                 mappa web

Se un anello della catena è fermo, i client risultano «connessi» ma i dati non circolano (vedi sez. 7).

Porte del server

PortaServizioUso
8089CoT SSL (eud_handler)Connessione dei client TAK, con certificato
8443HTTPS (nginx)API/Marti — richiede certificato client (mutual TLS)
8080HTTP (nginx)Web UI e REST
8087—TCP in chiaro: volutamente disabilitata

2 Collegare un dispositivo (EUD)

  1. Crea l'utente (o fai registrare l'operatore) sulla web UI del server.
  2. Genera dal server il data package con i certificati per quel dispositivo e trasferiscilo sul telefono.
  3. In ATAK: Settings → Network Preferences → Import (o importa il file dal gestore file). Il pacchetto configura da solo indirizzo, porta 8089 e certificati.
  4. Verifica che l'icona del server (in basso a destra sulla mappa ATAK) diventi verde.

Controprova lato server: web UI → pagina EUDs → il dispositivo compare con «Last event: Connected» e orario recente.

Nota

Un EUD può risultare «Connected» con data vecchia di mesi: è uno stato stantio rimasto dopo un riavvio del server, non significa che sia online. Fa fede l'orario dell'ultimo evento.

3 Vedersi in mappa

La mappa web mostra ogni dispositivo all'ultima posizione che ha trasmesso. «Connesso» non basta: servono tutte queste condizioni.

  1. Fix GPS sul telefono — in ATAK il proprio marker è ancorato alla posizione reale e in basso compaiono coordinate e precisione (es. +/- 21 m). Se vedi «NO GPS», esci all'aperto o verifica i permessi di localizzazione.
  2. Location reporting attivo — Settings → Reporting Preferences → strategia Dynamic o Constant. Da fermi gli invii si diradano (≈1/min): è normale.
  3. Connessione verde — icona server in basso a destra.
  4. Catena server sana — in particolare il servizio opentakserver-cot-parser (sez. 6 e 7).

Test del marker

Distingue in un colpo i problemi di trasporto da quelli di GPS: piazza un marker dalla mappa ATAK (pressione prolungata → punto). Se il marker compare sulla mappa web, tutto il canale funziona e il problema è solo il reporting di posizione del telefono.

4 Missioni (Data Sync)

Una missione è un canale di lavoro condiviso e persistente: chi si iscrive riceve tutto il contenuto (marker, disegni, foto, file) e ogni modifica successiva, incluso lo storico se entra a partita già iniziata. È cosa diversa da:

  • Channels — gruppi che segmentano chi vede chi sulla mappa generale;
  • Data Packages — invio manuale di un singolo file a un destinatario.

Prerequisito: il plugin

Data Sync non è incluso in ATAK base. Con ATAK installato dal Play Store: cerca «ATAK Plugin Data Sync» (editore TAK Product Center) sul Play Store, installalo, riapri ATAK e attivalo da Tools → Plugins. Serve su ogni dispositivo che partecipa.

Attenzione

I plugin ATAK sono legati alla versione dell'app: usa plugin della stessa provenienza di ATAK (Play Store con Play Store). Mescolare APK di tak.gov con l'app del Play Store crea incompatibilità.

Uso

  1. Creare: Tools → Data Sync → New Mission (nome, eventuale password). In alternativa dalla pagina Missions della web UI.
  2. Iscriversi: gli altri dispositivi aprono Data Sync, vedono l'elenco e fanno Subscribe.
  3. Lavorare: i contenuti si pubblicano nella missione e si sincronizzano a tutti gli iscritti; i ruoli distinguono chi può solo leggere da chi scrive.

5 Meshtastic: la radio quando manca la rete

Meshtastic è una rete di piccole radio LoRa a lunga portata (chilometri in campo aperto) che formano una mesh tra loro, senza SIM né internet. Il plugin Meshtastic per ATAK — già installato sui dispositivi del gruppo — collega ATAK a una di queste radio via Bluetooth: posizioni e chat viaggiano via LoRa tra gli operatori anche dove il telefono non ha copertura dati.

Cosa passa e cosa no

  • Passa: posizione dei compagni, chat testuale, marker essenziali.
  • Non passa: foto, video, data package, missioni — la banda LoRa è minima (poche decine di byte per messaggio). Meshtastic è il canale di riserva, non un sostituto del server.

Uso sul campo

  1. Accendi la radio Meshtastic e accoppiala al telefono via Bluetooth (prima volta: dall'app Meshtastic).
  2. Tutte le radio del gruppo devono avere la stessa configurazione di canale (stessa chiave/QR di canale, regione EU_868).
  3. In ATAK: Tools → Meshtastic Plugin → verifica che la radio risulti connessa e abilita l'inoltro della propria posizione.
  4. Gli altri operatori con radio sullo stesso canale compaiono in mappa come contatti normali.

Integrazione col server

OpenTAKServer può fare da gateway Meshtastic via MQTT: un nodo della mesh con accesso a internet inoltra il traffico al server (RabbitMQ espone il broker MQTT), e i dispositivi raggiungibili solo via LoRa compaiono sulla mappa web come gli altri EUD. Sul server sono già presenti tracce di questa configurazione (code mqtt-subscription-* su RabbitMQ); la configurazione del gateway si fa dalla sezione Meshtastic della web UI.

Attenzione

Come per Data Sync, la versione del plugin deve combaciare con quella di ATAK: installala dalla stessa fonte (Play Store con Play Store) e aggiornale insieme.

6 Telemetria del dispositivo

La scheda di ogni EUD nella web UI ha quattro grafici, alimentati da due fonti diverse:

  • Batteria — arriva col normale CoT di posizione: si popola da sola quando il dispositivo trasmette (servono più campioni e un refresh della pagina).
  • Heap, storage, traffico dati — sono le metriche, che ATAK invia solo se abilitate: Settings → cerca «metrics» → attiva raccolta e invio. Senza, restano vuoti per design.

Servizi

ServizioRuolo
opentakserverProcesso principale (Flask, API, web) — spawna gli eud_handler
opentakserver-cot-parserUnit dedicata: consuma i CoT da RabbitMQ e li scrive nel DB. Il main non lo avvia da solo — senza questa unit nessun dato viene salvato.
rabbitmq-serverSmistamento interno dei messaggi
nginxReverse proxy 8080/8443 e web UI

Aggiornamento

# dal clone del repo, come root
cd /home/ots/atakcivsaas && git pull && cd ots/scripts
./update-ots.sh --check   # confronta installata vs PyPI
./update-ots.sh           # backup + upgrade + restart + verifica
./update-ots.sh --ui      # aggiorna anche la web UI (serve unzip)
Attenzione

Dopo ogni upgrade verifica che il parser giri ancora: ps aux | grep cot_parser. E non modificare mai i file in site-packages/: il prossimo upgrade li sovrascrive — le personalizzazioni vanno nel repo (plugin o config).

Verifica rapida di salute

systemctl status opentakserver opentakserver-cot-parser --no-pager | grep -E "●|Active"
ss -tlnp | grep -E '8080|8089|8443'
tail -20 /home/ots/ots/logs/opentakserver.log

8 Troubleshooting rapido

SintomoCausa probabileAzione
EUD connessi ma invisibili in mappa; chat e data package non arrivano; tabelle cot/points vuote cot_parser non in esecuzione systemctl restart opentakserver-cot-parser e verifica con ps aux | grep cot_parser
Un solo dispositivo non compare, gli altri sì GPS o reporting del telefono Checklist di sez. 3 + test del marker
Dispositivo non si connette (icona non verde) Certificati / data package Reimporta il data package; nel log cerca la riga «ID'ed by cert» della connessione
curl sulla 8443 risponde 400 «No required SSL certificate was sent» Nessuna: è il mutual TLS che fa il suo dovere Niente — il test completo si fa con il certificato client
Log invaso da «AISStream websocket opened» o errori SkyFi Plugin non usati che tentano connessioni esterne Disabilita dalla UI o pip uninstall dal venv, poi riavvia il servizio
Un plugin disabilitato dalla UI continua a girare La disabilitazione ha effetto al riavvio systemctl restart opentakserver

Verificare i dati sul database

sudo -u postgres psql -d ots -c "SELECT COUNT(*) FROM cot;"
sudo -u postgres psql -d ots -c "SELECT device_uid, battery, timestamp FROM points ORDER BY id DESC LIMIT 5;"

Contatori che crescono mentre un client trasmette = catena sana. Fermi a zero = riparti dalla prima riga della tabella qui sopra.

Verificare lo smistamento (RabbitMQ)

rabbitmqctl list_queues name messages consumers

Ogni client connesso ha una coda di consegna col suo nome/UID. Code con messaggi accumulati e zero consumer indicano un consumer morto.
